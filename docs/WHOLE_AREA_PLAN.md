# 송도 타임스페이스 전체 구역 설계 (지도·사진 확보 전)

## 공간 모델

- **상권 경계(boundary)**: 사용자가 지도에 선으로 표시한 송도 타임스페이스 대상 구역의 외곽 다각형. 지도 앱의 캡처만으로 경계의 실제 지리 좌표를 확정하지 않음.
- **보행 통로(passages)**: 경계 안에서 사람들이 실제 이동할 수 있는 길. 이동할 수 없는 벽·상점 내부를 지나는 직선 지름길을 만들지 않음.
- **촬영 지점(nodes)**: 통로에서 한 위치를 가리키는 독립적인 촬영 지점. 서로 이동 가능한 위치를 direction별로 연결. 전체 구역 확장을 위해 임의 개수의 지점을 생성할 수 있게 설계.
- **점포(stores)**: 특정 동·층·호수 단위의 상점. 층별 필터를 적용하며 지도상의 아이콘은 정확한 주소 확인 후 배치.
- **거리 사진(views)**: 각 촬영 지점에서 바라보는 앞/뒤/좌/우 네 방향 일반 사진. 선택한 층이 2층·3층이어도 최초에는 1층 외관 사진에서 출입구와 호수를 안내. 실내 거리뷰로 오인하게 만들지 않음.
- **가게 외곽선(annotations)**: 촬영 사진에서 특정 점포의 외곽선을 다각형으로 지정하는 영역. 사진을 바꾸면 기존 영역 좌표도 다시 확인해야 함.

## 사용자가 제공한 전체 지도 자료 처리

현재 첨부한 네이버 지도 캡처의 선은 **서비스 대상 범위**로 사용해야 함. 지도에서 거리의 길이, 건물별 출입구, 영업 점포의 정확한 층수·호수, 촬영 지점 위치를 검증할 수는 없음. 따라서 실제 측량 지도로 오인되지 않게 지도 편집기로 경계·통로·노드를 보정하도록 구현.

## 실제 위치를 입력하는 방법

1. 배포 후 `/map-editor`에 들어가 전체 지도 이미지를 **브라우저에서 임시 등록**한다. 지도 이미지는 외부에 업로드되지 않는다. 공개 서비스에서 원본 지도 이미지를 배포하기 전에는 라이선스를 확인한다.
2. `상권 경계`에서 사용자가 표시한 외곽선을 따라 꼭짓점을 찍는다.
3. `보행 통로`에서 실제 길을 표시한다. 통로가 여러 개면 각각 `새 통로`로 추가한다.
4. `촬영 지점`에서 처음 4개 지점을 수정하거나 새 지점을 추가하고, 통행 가능한 이웃 지점만 방향별로 연결한다.
5. `점포 위치`에서 점포를 해당 건물/층으로 구분해 위치를 지정하고 촬영 지점과 연결한다.
6. `변경사항 저장`을 누르고 소비자용 `/` 화면에서 작동 여부를 확인한다.
7. `지도 설정 JSON 내보내기`로 백업한다. 이 JSON에는 지도 이미지 자체는 포함되지 않는다.

## 촬영 후 작업 방법

1. `/street-editor`에서 지점과 방향을 선택한다.
2. JPG/PNG/WEBP 사진(20MB 이하)을 업로드한다. 같은 브라우저의 소비자 페이지에서 미리보기 가능.
3. 점포 외곽선을 클릭으로 지정한다.
4. `영역 저장` 및 `JSON 내보내기`로 좌표를 보관한다.
5. 모든 이용자가 볼 수 있도록 **공개 배포**할 때는 운영자가 검토한 사진을 `public/street/`에 넣고 `src/data/streetNodes.ts`의 사진 경로를 등록해야 한다. 동적으로 추가한 지점도 소스 데이터로 반영하거나 서버에 등록할 별도의 운영 기능이 필요하다.

## 한계 / 사실관계

- 현재 기본 촬영 지점 4개와 시연 점포 6개는 **임시 배치**입니다. 첨부 지도에서 정확한 구조를 자동 추출했다고 주장하지 않습니다.
- 현재 360° 파노라마나 AI 자동 점포 감지, 공공데이터 API 자동 점포 갱신, 실측 길찾기는 구현하지 않았습니다.
- 로컬 브라우저에 저장한 지도 배경·지도 설정·사진·점포 영역은 다른 사용자에게 공유되지 않습니다.
- 지형 분석은 실제 보행 동선 조사와 건물 출입구 확인을 통해 확정해야 합니다.
- 거리 사진에는 행인 얼굴·차량 번호판 같은 개인 식별 요소가 있을 수 있으므로 공개 전 검토·가림 처리를 해야 합니다.
