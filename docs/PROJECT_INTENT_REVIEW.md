# 기획서·참가신청서와 현재 홈페이지 비교

검토일: 2026-11-05. 기준 자료는 사용자가 제공한 「2026년 페스티벌 참가신청서_최종.hwp」의 신청서·기획안·캐릭터 설정이며, 구현 상태는 현재 저장소의 코드를 기준으로 확인했습니다. 신청자 이름·연락처·서명 등 개인정보와 원본 신청서는 홈페이지나 이 저장소에 복사하지 않았습니다. 외부 통계·참고문헌의 최신성 검증은 이번 검토 범위에 포함하지 않았습니다.

## 이 서비스가 하려는 일

핵심은 가게 목록을 보여주는 것 자체가 아니라, **점주의 홍보를 손님의 거리 탐색·발견·방문으로 연결하고, 한 번의 방문이 주변 다른 점포의 다음 방문으로 이어지게 하는 것**입니다.

- 맛: 음식점·카페·디저트 등 먹거리.
- 멋: 문화·뷰티·사진·소품·체험 등 다양한 동네 경험.
- 시작 지역: 송도 타임스페이스 일부 구간.
- 확장 방향: 제물포에 적용·검증한 뒤 다른 인천 상권으로 확산.
- 점주 역할: 어려운 명령어 대신 일상 문장으로 상황과 목적을 설명하고, 내용을 최종 확인한 뒤 소식을 공개.
- 캐릭터 역할: 포물이는 제물포의 정겨움과 초보 이용자의 시선, 도송이는 송도의 새로움과 디지털 탐색을 안내. 백령도에서 여행을 떠난 형제라는 설정.

## 현재 구현과의 차이

| 기획의 핵심 | 현재 코드에서 확인한 상태 | 판단 |
| --- | --- | --- |
| 실제 거리를 보며 점포 발견 | 방향별 사진·층별 지도·사진 영역 연결·방향별 가게 카드가 있음 | 핵심 기반은 있음. 실제 촬영 사진으로 이어지는 진입을 더 강조할 필요 |
| 점주 홍보와 손님용 화면 연결 | 담당 점포 계정·게시 한도·종료일·직접 게시·공개 이벤트 조회 경로가 있음 | 운영 환경에서 점주 게시 → 손님용 공개까지 한 번의 시연 검증이 필요 |
| 다음 방문 장소 추천 | 손님용의 추천 예시는 등록된 aiScore가 높은 가게 하나를 선택함. 사진의 다음 지점 이동은 존재함 | **다음 장소 추천과 다음 촬영 지점 이동은 다름. 기획의 가장 큰 미충족 부분** |
| 점포 상황에 맞춘 생성형 AI 홍보 | 현재는 세 개의 고정 예시 템플릿. 입력한 목적과 조건 전체를 분석하는 실제 AI 호출이 아님 | 'AI가 조건을 이해해 생성한다'고 표현하면 구현과 어긋남 |
| 점주가 최종 확인·승인 | 현재는 초안 저장 후 점주가 직접 게시. 관리자 사전 승인 방식은 아님 | 신청서의 '승인'은 점주의 최종 확인으로 설명하고 예전 운영 설명을 정리해야 함 |
| 제물포·송도 연결 | 현 데이터·탐색은 송도 중심, 제물포는 확장 구상 | 지역 선택 화면을 먼저 열기보다 준비 단계임을 표시해야 함 |
| 캐릭터를 통한 로컬 브랜딩 | 이미지 활용은 있으나 지역·성격·형제 이야기가 부족했음 | 이번 캐릭터북에 이름·역할·이야기를 반영 |

## 추가·보완 우선순위

### 1. '여기 다음에는 어디 갈까?'를 손님용 상세에 추가

가장 먼저 권하는 기능입니다. 가게 상세를 본 뒤 다른 업종의 주변 장소 2~3개를 제안하고, **왜 이 장소인지**와 거리 사진으로 이동하는 버튼을 함께 보여주세요. 예를 들어 식사 → 카페 → 사진·체험 순서처럼 상권 안에서 다음 행동이 이어져야 합니다.

초기에는 업종·태그·층·연결된 촬영 지점 기반의 설명 가능한 규칙으로 시작하고 '추천 예시'로 표시할 수 있습니다. 실제 AI를 연결하기 전부터 AI 추천이라고 단정하지 마세요. '다음 촬영 지점' 버튼은 이 기능의 대체물이 아닙니다.

### 2. 점주 게시 전 직접 수정할 수 있는 문구 편집 추가

현재 문구는 확인·선택·복사는 가능하지만 화면 안에서 행사 조건을 자유롭게 고치는 편집 흐름이 약합니다. 점주가 가격·메뉴·시간·혜택을 수정하고 최종 문구를 확인한 뒤 게시하도록 만드는 것이, 생성형 AI 연결보다 먼저 유용합니다. 업종에 맞지 않는 '학생 인증·음료 서비스'가 반복되는 고정 템플릿도 정리할 필요가 있습니다.

### 3. 실제 AI 문구 생성은 서버 경로로 연결

실제 생성형 AI를 붙이려면 서버 API, API 키 보관, 점포 정보·입력 목적·제약 조건 전달, 실패 시 처리와 결과 검수가 필요합니다. API 키를 브라우저 코드에 넣지 않습니다. 연결 후에도 점주의 최종 확인과 게시 한도는 유지하는 방향이 신청서 의도에 맞습니다.

### 4. 점주 → 손님용 연결을 메인에서 짧게 보여주기

'가게 소식 작성 → 점주 확인·게시 → 거리에서 발견 → 다음 장소'라는 흐름을 네 단계로 보여주세요. 이번 가이드북에는 기획 의도와 실제 게시 방식을 설명했지만, 메인의 짧은 서비스 소개에도 이 흐름을 강조하면 링크 모음처럼 보이는 느낌을 줄일 수 있습니다. 실제 소식을 공개 예시로 보여줄 때는 시연 데이터 여부를 명시해야 합니다.

### 5. 실제 거리 사진의 진입과 현재 시범 범위 강조

새 배너 그림은 브랜딩에 도움이 되지만, 이 서비스의 차별점은 실제 촬영한 거리를 탐색하는 경험입니다. 검색뿐 아니라 '실제 거리 사진 둘러보기'를 눈에 잘 보이는 진입으로 두는 것이 좋습니다. 일러스트를 실제 점포 사진처럼 설명하지 않고, 송도 시범·제물포 확장 예정도 명확히 구분하세요.

### 6. 성과는 '방문했다'가 아니라 관찰 가능한 행동부터

후속 측정 지표는 가게 상세 조회, 소식 확인, 즐겨찾기, 다음 장소 선택 등의 클릭 흐름부터 잡는 것이 좋습니다. 단순 조회·클릭을 실제 오프라인 방문이나 매출 증가로 표현해서는 안 됩니다. 운영 동의와 실제 데이터를 확보한 뒤 반응에 기반한 홍보 개선으로 이어가세요.

## 이번 요청에서 실제 반영한 것

- 매장 정보에 전용 카페 실내 배경을 새로 만들고, 로그인 전 안내와 담당 매장 상단 모두에 전체 배경으로 적용.
- 서비스 역할 이름을 손님용 / 점주용 / 관리자로 정리.
- 메인의 중복 이용 방법을 네 권의 안내서와 캐릭터 위젯으로 교체.
- 손님용·점주용·관리자 가이드에는 현 기능과 게시 방식, 준비가 필요한 기능을 구분해 설명.
- 포물이·도송이의 이름, 지역, 성격, 복장 의미와 형제 이야기를 캐릭터북에 반영.

위 우선순위 기능들은 제안이며, 다음 장소 추천·문구 편집·실제 AI 생성·새 분석 기능을 이번 요청에서 구현했다고 의미하지 않습니다.
