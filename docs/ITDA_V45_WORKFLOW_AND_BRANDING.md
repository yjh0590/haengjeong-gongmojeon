# ITDA v4.5 — 인천색 UI 및 점주 홍보안 승인 연동

## 업데이트 개요

### 디자인

| 영역 | 주색 | 활용 |
|---|---|---|
| 메인 | `#0079c1` 인천 블루 | 로고, 카드 강조, 인천 로컬 브랜드 |
| 소비자 | `#0079c1` + `#1f3c95` | 지도 탐색, 중요 버튼, 송도·연수권 표시 |
| 점주 | `#ff601f`에서 착안한 따뜻한 주황 | 마케팅/홍보 CTA와 카드 강조. 기존의 따뜻한 분위기 유지 |
| 관리자 | `#22804d` 녹색 | v4.4 관리자 대시보드 스타일 유지 |
| 확장 지역 | `#093190` 제물포 색상 | '확장 예정' 지역 안내에만 사용 |

- 사용자가 공유한 색상표에서 영감을 받은 디자인입니다. 공식 기관이 인증하거나 후원한다는 의미는 아닙니다.
- 인천대/인천시 로고나 제3자의 지도 캡처를 새로 포함하지 않았습니다.
- 맛·멋·이벤트의 의미별 지도 아이콘 색은 유지했습니다.
- 색상 전용 변경은 `src/styles/IncheonBrand.css`에 모아 두었습니다. 나중에 디자인을 조정하기 쉽습니다.

### 데이터 흐름 (v4.5)

1. 관리자가 `editor.itda.ink/catalog`에 점포 목록을 게시합니다.
2. `supabase/002_owner_promotion_workflow.sql`을 Supabase SQL Editor에서 실행합니다. **기존 `001_publication.sql` 실행 후** 사용합니다.
3. Supabase Authentication에서 점주 계정을 생성하고 인증/비밀번호 설정을 마칩니다. **관리자와는 별도의 계정**을 쓰는 게 좋습니다.
4. 점주의 `auth.users.id`에 해당 점포 ID를 `itda_owner_stores`로 배정합니다. 아래 예시 이메일/ID를 실제 값으로 바꿔 실행합니다.

```sql
insert into public.itda_owner_stores (user_id, store_id)
select id, 1 from auth.users where email = 'owner@example.com'
on conflict do nothing;
```

5. 점주가 `owner.itda.ink` 로그인 → 배정 점포 선택 → 예시 기반 홍보안 작성 → **관리자 검토 요청**.
6. 관리자가 `editor.itda.ink/promotions`에서 승인/반려합니다.
7. 승인된 경우 Supabase DB 함수가 해당 점포의 공개 이벤트 문구를 갱신하며, 소비자는 `customer.itda.ink`를 새로 열거나 새로고침해서 확인할 수 있습니다.
8. 홍보 종료일 이후에는 소비자 화면에서 이벤트 문구를 숨깁니다.

**중요:** 지금 점주 홍보안 자동 생성은 생성형 AI API가 아닌 시연용 템플릿입니다. 실제 AI 연동은 별도 단계입니다.

## 검증 시나리오

1. 메인 `itda.ink`에서 소비자·점주 링크가 각각 서로 다른 서브도메인으로 열리는지 확인.
2. 소비자 `customer.itda.ink`에서 지도·층 필터·점포 검색·즐겨찾기가 동작하는지 확인.
3. `editor.itda.ink`에서 Supabase 관리자 로그인 → `/catalog` 게시본 확인 및 필요시 점포 목록 게시.
4. 비로그인 상태에서 `editor.itda.ink/promotions`에 접근하면 관리자 로그인 화면으로 이동되는지 확인.
5. 점주 계정 로그인 후 *배정된 점포*만 선택·제출할 수 있는지 확인.
6. 관리자 승인 전에는 홍보 내용이 소비자에게 보이지 않는지 확인.
7. 승인 후 새로고침 시 해당 가게의 이벤트만 바뀌는지 확인.
8. 홍보안 반려 시 이벤트 문구가 바뀌지 않는지 확인.
9. 콘솔/네트워크 오류가 있는지 확인. 비밀 `service_role`, `sb_secret_` 키는 GitHub와 Vercel의 `VITE_` 변수에 넣지 않기.

## 남은 작업

- 실제 360도 파노라마, 공개 사진 파일 저장소, 실측 지도, 실제 점포 데이터는 미구현 또는 미검증입니다.
- 개별 점주가 가게 정보를 직접 수정하는 기능은 아직 없습니다. 현재 점주의 역할은 홍보안 제출입니다.
- 데이터베이스는 점주가 배정 점포에만 제출하도록 RLS로 제한합니다. 사용자 인증과 점포 할당이 필요합니다.
- 도메인 전체의 사용성/실제 서비스 성능은 Vercel 배포 후 검증해야 합니다.
