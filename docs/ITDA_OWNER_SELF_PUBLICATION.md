# 점주 직접 게시 · 관리자 디자인 변경

관리자 대시보드는 제공된 녹색 사이드바 시안에 맞춰 변경했습니다. 현황 카드와 층별 차트는 실제 게시본 또는 현재 브라우저의 초안 데이터를 사용합니다. 방문자·가입자 통계는 임의로 만들지 않습니다.

점주 홍보는 승인 대기 방식에서 **담당 점포 계정의 직접 게시**로 변경했습니다. 기본값은 **점포당 하루 3회**, 한국시간(Asia/Seoul) 자정에 초기화됩니다.

## 운영 서버 활성화

프런트엔드 배포와 데이터베이스 변경은 별개입니다. 아래 SQL이 운영 프로젝트에 적용되기 전에는 새 직접 게시 버튼과 정책 변경 기능이 비활성화됩니다. 화면 배포만으로 서버 설정이 완료되었다고 판단하지 마세요.

1. 사용 중인 Supabase 프로젝트에 연결합니다.
2. 기존 `001_publication.sql`, `002_owner_promotion_workflow.sql`, `003_public_media_storage.sql` 적용 여부를 확인합니다.
3. [`004_owner_self_publication.sql`](../supabase/004_owner_self_publication.sql) 전체를 프로젝트 소유자의 SQL Editor에서 실행합니다. 트랜잭션으로 적용되며 재실행할 수 있습니다.
4. 관리자 `/promotions`에서 한도가 3회, 직접 게시가 허용 상태인지 확인합니다.
5. 담당 점포가 배정된 점주 계정으로 로그인해 직접 게시를 확인합니다.

관리자·점주 인증과 점포 배정은 기존 설정을 유지합니다. 비밀번호, 서비스 키, 데이터베이스 접속 정보는 프런트엔드 환경변수에 추가하지 않습니다.

## 사용 방법

- 점주: 홍보하기 → 가게 선택 → 예시 홍보안 생성 → 내용 선택 → 초안 저장 → 종료일 선택 → 직접 게시.
- 게시 한도는 점포의 모든 계정과 기기에서 공유합니다. 문구를 바꿔 다시 게시해도 1회입니다.
- 게시하지 않은 초안 저장, 실패한 검증, 같은 요청의 네트워크 재시도는 횟수에 추가되지 않습니다.
- 중단되거나 새 문구로 대체된 게시도 그날 사용 횟수에 포함됩니다.
- 종료일은 한국시간 오늘부터 90일 이내로 정합니다.
- 관리자: 홍보 게시 관리에서 현재 게시·이전 내역을 보고 게시를 중단할 수 있습니다. 일일 한도는 1~30회로 변경하거나 직접 게시 전체를 일시 중지할 수 있습니다.
- 기존 승인·반려·대기 기록은 이력으로 남깁니다. 과거 대기 요청을 자동 게시하지 않습니다. 점주가 새 흐름에서 직접 게시합니다.

## 데이터 처리

- `itda_publish_owner_promotion` RPC가 로그인, 담당 점포, 공개 점포 존재, 문구 길이, 종료일, 일일 한도를 한 트랜잭션에서 검사합니다.
- 점포별 트랜잭션 잠금으로 여러 계정의 동시 게시를 직렬화합니다. 클라이언트가 사용 횟수나 게시 시각을 지정할 수 없습니다.
- 클라이언트 요청 UUID와 사용자 ID의 고유 인덱스로 응답 유실 후 재시도가 중복 게시·차감으로 이어지지 않게 합니다.
- 직접 INSERT와 기존 승인 RPC의 실행 권한은 회수합니다. 점주는 공개 게시본 자체를 수정할 수 없습니다.
- 소비자에게는 `itda_live_promotions`의 공개 문구·점포 번호·종료일·활성 상태만 제공합니다. 계정 정보나 비공개 SNS 초안은 공개하지 않습니다.
- 점주 이벤트는 기본 점포 게시본 위에 별도로 적용됩니다. 관리자가 오래된 초안을 전체 게시해도 점주의 최신 이벤트를 덮어쓰지 않습니다.
- 중단·만료된 이벤트는 숨기며 과거 이벤트를 되살리지 않습니다. 새 점주 게시가 이 상태를 대체합니다.
- 소비자 페이지는 새로 불러올 때 최신 게시를 읽습니다. 이미 열린 탭은 포커스를 되찾거나 최대 15초마다 갱신합니다.

## 검증

```text
npm ci
npm run test:promotions
npm run build
```

`test:promotions`는 메모리 내 PostgreSQL(PGlite)에 실제 001·002·004 SQL을 적용해 권한, 다른 점포 접근 거절, 공동 한도, 네 번째 게시 차단, 요청 재시도, 중단 후 횟수 유지, 자정 경계, 관리자 정책, 공개 조회 범위, 이벤트 덮어쓰기를 검증합니다. 운영 DB에 쓰지 않습니다. PGlite는 단일 연결이므로 다중 연결의 실제 동시 실행 부하를 측정하는 테스트는 아닙니다.

로컬 브라우저 통합 검증은 별도의 가상 Supabase 주소와 테스트 DB만 사용합니다. 운영 관리자 인증을 우회하는 코드나 테스트 계정은 배포하지 않습니다.

## 점주가 직접 소식 내리기 (005)

점주용 '내 계정'의 **소식 내리기** 버튼은 [`005_owner_withdraw.sql`](../supabase/005_owner_withdraw.sql)이 적용된 서버에서만 동작합니다. 적용 전에는 버튼을 눌러도 "005 SQL이 아직 적용되지 않았어요" 안내가 나오고, 지금처럼 관리자만 게시를 중단할 수 있습니다.

1. 004가 적용된 Supabase 프로젝트의 SQL Editor에서 `005_owner_withdraw.sql` 전체를 실행합니다. 트랜잭션으로 적용되며 다시 실행해도 됩니다.
2. 점주는 자기에게 배정된 가게의 소식만 내릴 수 있습니다. 다른 가게나 없는 소식은 같은 오류 문구로 거부합니다. 관리자는 기존처럼 모든 소식을 내릴 수 있습니다.
3. 내린 소식의 게시 횟수는 돌려주지 않습니다.
