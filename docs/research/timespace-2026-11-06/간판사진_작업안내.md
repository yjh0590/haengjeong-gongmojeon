2026-11-06 수집. 저장한 387건의 출처별 기록을 기준으로 매장 이름과 주소를 대조하고 사진에서 간판을 직접 확인했습니다.

- 인터넷에서 확보한 간판 사진: 6장 (`public/street/timespace-signs/`)
- 기존 사용자 촬영 사진: 3장 (`public/street/c-block/`, 원본 유지)
- 사진이 연결된 카드: 9개. 전체 입점 매장의 사진을 확보한 것은 아닙니다.
- 나머지 378건은 사진 미확보 기록입니다. 동일 매장의 중복 출처도 포함하므로 미확보 매장 수와 같지 않습니다.
- 전 매장의 현재 영업 상태, 최신 간판, 실제 거리에서의 좌우 순서는 확인되지 않았습니다.

## 보기

손님 화면 상단 **간판 찾기**. 로컬 미리보기는 `http://127.0.0.1:4190/street-demo?view=signs`입니다.

층 → 동 → 호수 순으로 정렬하며 기본 화면에는 사진이 연결된 9개 카드가 표시됩니다. `사진 없는 수집 기록도 보기`를 켜면 387개 원본 기록을 검색할 수 있습니다. 이 기록들을 확인 없이 같은 가게로 합치지 않았습니다. 18개씩 페이지를 나눕니다.

카드에는 간판 사진·상호·업종·층·동·호수·위치 판단 근거·출처를 표시합니다. 클릭하면 사진을 원본 비율로 크게 보고 해당 사진의 게시 시점, 대조 메모, 정보/사진 출처를 확인할 수 있습니다. 원본에 없는 메뉴·가격·영업시간이나 가짜 지도 좌표는 만들지 않았습니다. 현재 관리자 게시 데이터는 변경하지 않습니다.

## 제외 및 미확보

- 다이닝코드의 음식 사진은 간판 사진으로 사용하지 않았습니다. 직접 HTML 접근은 403이었으며 웹 검색에서 보이는 공개 사진만 후보로 확인했습니다.
- 타임스페이스 검색에 나온 더더·완미족발 등의 주변 건물 사진은 하모니로 158 주소와 달라 제외했습니다.
- 마끼에·마메의 내부 좌석 사진도 제외하고 입구 간판이 보이는 사진만 선택했습니다.
- 약손명가·보니보니·숯멍 등 나머지 기록에는 간판과 지점이 함께 확인되지 않은 사진을 임의 연결하지 않았습니다.

## 갱신과 검사

1. 새로운 사진을 저장하고 `간판사진_매칭.json`에 원본 기록 ID·출처·검증 메모를 추가합니다.
2. `node scripts/build-storefront-catalog.cjs`로 `src/data/storefrontCatalog.json`을 재생성합니다.
3. `node scripts/test-storefront-catalog.cjs`, `npm run build`, `npm run lint`를 실행합니다.

자동 검사는 원본 기록 유지, 중복 ID, 정확한 ID별 사진 연결, 파일 존재, JPEG 형식, 층별 연결을 확인합니다. PC 1440px·태블릿 768px·모바일 390px/320px에서 사진 로딩, 잘림 없는 비율, 검색, 층 필터, 페이지 이동, 큰 사진 대화상자와 뒤로 가기를 확인했습니다.
