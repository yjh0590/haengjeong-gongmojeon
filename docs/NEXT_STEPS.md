# 후속 개발 로드맵 — 공모전 본선

## 지금 적용한 범위

- 소비자 화면을 지도 중심으로 개편, 기존 점주 화면 유지
- 클릭 가능한 **시범 구역 안내도**와 방향별 사진 연결
- 검색·카테고리 필터·즐겨찾기·등록된 이벤트 표시
- 사진 속 점포 외곽선을 수동 등록하는 `/street-editor` 도구

## 실제 상권 데이터 수집이 먼저 필요한 이유

현재 `src/data/stores.ts`의 A~F 점포는 모두 예시입니다. 실제 상권에 적용하려면 점포별로 다음 필드를 확인해야 합니다.

| 정보 | 용도 | 주의 |
|---|---|---|
| `storeId` | 동일 점포 연결하는 고유 식별자 | 상호명이 바뀌어도 데이터 이력 유지 |
| 상호명·업종 | 검색·필터 | 점주/공공데이터 검증 |
| 건물 동·층·호수 | 여러 층 가게와 점포 분리 | 같은 건물 주소만으로 구별 불가 |
| 도로명 주소 및 위·경도 | 실측 지도·외부 길찾기 | 주소 기반 지오코딩과 검증 필요 |
| 촬영 지점 좌표·방향 | 지도와 거리뷰 연결 | 휴대폰 방향·촬영 날짜 기록 |
| 사진별 가게 다각형 | 외관 하이라이트 | 실제 촬영 자료를 보고 직접 라벨링 |
| 이벤트 기간·유효 상태 | '오늘의 발견' | 현재는 유효기간 필드가 없음 |

## 1차: 실측 지도 및 촬영 데이터

1. 송도 타임스페이스 일부 구간 점포 정보 5~10곳 실사 검증
2. 실제 좌표·건물 동/층/호수, 출입구 위치 데이터 추가
3. 실측 지도를 사용할 경우 적법한 지도 SDK·타일 제공자 선정 및 API 이용 조건 검토
4. 스마트폰 촬영 사진 추가, 1~4 촬영 지점의 연결 방향 검증
5. `/street-editor`에서 실제 가게 외곽선 지정 → JSON 파일 내보내기 → `builtInFacades`로 프로젝트에 포함
6. 사람·차량번호판 등 개인정보 요소 블러 처리 후 공개

## 2차: 파노라마 및 AI 인식

1. 완전한 360×180 파노라마 촬영 또는 촬영·스티칭 테스트
2. 실제 촬영 위치 간 이동 연결 및 입구 강조, 스마트폰 회전 UI 검증
3. AI가 간판 문자·가게 외곽선을 **후보**로 추천하고 관리자가 검증하는 편집 워크플로
4. AI가 추천한 점포와 공공 점포 기록 간 동일 개체 매칭·신뢰도 표시

## 3차: 점포 변경 자동 감지

1. 데이터 출처 후보: 지방행정 인허가, 공공 상가업소 정보 등 (공식 제공 범위·갱신주기·라이선스 확인 후 선정)
2. 수집한 데이터에 `source`, `sourceId`, `lastCheckedAt`, `observedAt` 저장
3. 기존 상호·주소·동/층/호수·업종과 비교하여 `new`, `changed`, `possiblyClosed` 후보 생성
4. 높은 확신도는 ‘확인 필요’ 알림, 낮은 확신도는 수동 검토로 분류
5. 관리자 승인 뒤 **점포 정보만 갱신**; 과거 점포를 삭제하지 않고 이력 보존
6. 사진 촬영 날짜가 점포 변경 이전이면 해당 거리 사진에 ‘재촬영 필요’ 표시
7. 정기 작업(예: 매일 또는 주 1회)과 관리자 알림 도입. 데이터 제공처 갱신주기보다 자주 확인해도 실시간이 되지는 않음

**중요:** 현 ZIP에는 실제 API 연동·서버 DB·자동 업데이트 기능이 구현되지 않았습니다. 배포용 운영 계정이나 점주별 접근 권한도 아직 없습니다.

## 본선 발표에 사용할 때

- **실제 시연:** 지도 탐색·저장·사진 연결·점포 영역 편집
- **시연용 데이터임을 명시:** A~F 가게, 지도 좌표, 추천 점수, 홍보 문구
- **향후 계획:** 360° 파노라마, AI 점포 인식, 공공데이터 변경 감지, 점주 계정/쿠폰, 제물포 확장
